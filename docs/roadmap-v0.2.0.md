# v0.2.0 设计：纸间 Paperlane、精确尺寸与多打印机

状态：下一版方案，未发布、未改名、未部署。下文的新增设置与多打印机功能尚未实现，不能视为当前兼容能力。名称已确定为**纸间 Paperlane**，目标仓库名 `paperlane`。

## 现状与问题

v0.1.0 可以读取 IPP 属性，但实际渲染和发送仍固定为 4 × 6 英寸、300 dpi、JPEG，默认发送四边 0 边距、高质量和不缩放参数。当前只有一个通过环境变量指定的打印目标。

仅把打印机地址换成其他品牌并不足以保证兼容。设备可能没有相应相纸、不支持无边距、不接受 JPEG，或不能可靠上报任务完成。下一版必须先协商能力，再允许选项和打印。

## 1. 将相纸尺寸与照片尺寸分开

### 用户界面

1. **选择打印机**：如家中照片机或其他已添加设备。
2. **选择相纸**：从设备能力读取，并显示真实宽高（毫米），品牌习惯名称只作为辅助。
3. **设置照片尺寸**：单张照片或拼版格子可用预设，也可输入宽、高、单位（毫米/厘米/英寸）。
4. **选择布局、裁剪与边距**：预览显示纸张外框、可打印范围、照片尺寸与用纸数量。
5. **校验后打印**：不能放入纸张或不能由设备保证的参数，不静默替换。

例如，在一张 4 × 6 英寸相纸上，排两张 76.2 × 76.2 mm 方片，或者多张 35 × 45 mm 照片。更改照片大小不等于要求打印机接收任意大小的纸。

### 能力查询与计算

- 显式请求 `media-col-database`，兼容设备不会在默认能力查询中返回该完整属性。
- 优先读取 `media-col-ready`/`media-ready`，区分“支持的纸张”和“设备上报当前已装的纸张”；后者仍可能需要用户确认，不能替代物理装纸检查。
- 用 `media-size-supported`、相纸集合中的尺寸与四边边距确定可打印范围。IPP 相纸尺寸及边距使用百分之一毫米。
- 只在设备支持的尺寸/范围内允许自定义**相纸**；设备上报不完整时允许保存“手动配置、未验证”的机型配置，但不能自动宣称兼容。
- 照片宽高以整数微米或等价精确单位保存，渲染时按 `pixels = mm / 25.4 × dpi` 换算；分别处理 X/Y 分辨率，并支持 IPP 的 dpi/dpcm 单位。
- 从 `printer-resolution-supported`、质量、缩放和边距组合中选择设备支持的值，不再固定 300 dpi、无边距和高质量。不能把孤立属性的任意组合都视为支持，应以有效的 media-col 组合与校验为准。
- 优先使用严格参数校验（`ipp-attribute-fidelity=true`），检查 Validate-Job 的响应状态和 Unsupported Attributes；存在忽略/替换时回到预览说明差异，不把所有 successful 状态都当成精确尺寸得到保证。
- Validate-Job 不验证实际图像观感、纸张机械误差与无边距放大。提供标尺测试页和手动校准；真实尺寸与颜色仍需实物验收。

## 2. 多品牌、多打印机

### 下一版优先支持的路径

**通用 IPP JPEG 后端**：支持浏览器手动添加 `ipp://`/`ipps://` 地址，查询能力后保存设备配置，选择默认设备并在打印前切换。品牌不是判断条件；具体型号须同时满足协议、JPEG、相纸/分辨率组合和任务状态条件。

**发现机制**：优先手动添加，局域网 DNS-SD/mDNS 发现作为可选入口。Docker bridge 中不保证跨宿主机接收到组播；发现失败时仍可手动填写，不能为此默认要求 host 网络或修改主路由。

**其他格式/老设备**：为 CUPS 后端预留接口，后续可将 PDF 等页面交给独立的 CUPS/Printer Application 转换。PWG Raster/URF-only、USB/专用驱动设备不能由当前 JPEG 发送器直接兼容，不能把“预留接口”写成“已支持”。私有蓝牙、只允许厂商 APP 或云端协议的型号需要独立研究。

### 设备配置与任务模型

- 每台设备有稳定的内部 ID、名称、URI、后端类型、能力快照与更新时间、默认相纸及“未验证/参数校验/实物通过”等状态。
- 设备配置只保存在本机服务数据中，不能进入公开仓库。仅登录的管理界面可修改目标；限制协议与目标、超时和响应大小，不开放无需认证的网络探测接口。
- 对 IPPS 使用证书校验；不为兼容设备全局关闭 TLS 校验。
- 预览生成时固定 `printer_id`、能力版本、相纸、有效边距、分辨率、排版和文档格式。切换打印机或关键参数必须重新预览，不能把已生成页面直接发给另一台机器。
- 任务持久化目标设备和真实 IPP job-id，查询状态必须回到原设备，不能因用户切换默认打印机而查询错误队列。
- v0.2.0 先保留单实例、串行打印调度；不承诺跨设备并行，避免过早放大照片归档冲突。
- 同一源照片不能同时被两个未结束的批次占用。全部所需页/份数完成后才归档，不确定、失败或取消时保持保守处理，不自动重发。
- 列出“参数已验证”和“实物已通过”的具体机型，佳能、爱普生、惠普等品牌不作为整体兼容承诺。

## 3. 更名与升级

- 页面、图标文字、README 与包元数据更名为“纸间 Paperlane”。
- 正式发布 v0.2.0 时将仓库改名为 `paperlane`，确认目标名称可用；GitHub 链接重定向不代表本地 Git remote、书签或镜像地址都会自动更新。
- 新版本提供新地址说明与旧路径迁移文档。工作目录、data 数据、已有自定义密码、历史任务与归档记录保留；不因品牌改名自动删除旧 Docker 项目或重新初始化数据。
- 如更换镜像名称，先发布新镜像，再说明旧镜像的过渡安排；没有实际构建/推送的镜像不能写成可拉取。
- 从旧 `PRINTER_URI` 初始化第一台设备，旧的 6 寸使用习惯保留；旧预览按旧规则完成或明确过期，不在升级中转投新设备。

## 拟定验收

- [ ] 不同尺寸、非正方分辨率、非零边距和不完整能力的合成测试。
- [ ] 支持 media-col 组合、尺寸范围与格式协商，拒绝不可打印的参数组合。
- [ ] 一台富士与至少一个其他品牌的具体机型完成协议、预览、真实出片与毫米标尺测试，之后才提升兼容状态。
- [ ] 两台模拟打印机的 job-id 不串台，切换目标使预览失效。
- [ ] 网络中断、打印中重启、多份失败、改名升级后不重复打印、不错误归档。
- [ ] 旧密码、照片目录、数据库与已完成记录升级回归。
- [ ] 通过 CI、兼容性说明和发布说明后，再合并并发布 v0.2.0。

## 本次可用的研究工具

新增 `scripts/probe_printer.py`，只执行 Get-Printer-Attributes，不打印、不修改设备。它显式请求完整相纸数据库，并排除设备名称、UUID、URI、序列号和位置等身份信息。

```sh
python scripts/probe_printer.py ipp://printer.local:631/ipp/print
```

这份工具与方案不改变当前应用的固定 6 寸行为，也不代表已完成下一版的多品牌支持。
